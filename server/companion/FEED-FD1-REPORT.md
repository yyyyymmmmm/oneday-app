## 改了什么（只动 `modules/oneday_bridge.py`）

1. **分级（代码规则，`_feed_event_grade`）**：A 级四路——①待批新增
   （kind=approval）②监测告警级 ③里程碑勾完（kind=milestone）
   ④kanban 任务转失败/阻塞（state ∈ {failed, rejected} ∪
   `_KANBAN_BLOCKED_STATUSES`；状态词取自桥内 ledger KANBAN_MAP 既有
   映射，不自创）。其余（新点子/简报/任务完成/监测普通变化…）为 B。
2. **②的落法（如实交代）**：本桥监测无告警规则字段，change 记录只有
   内容摘要——§1.6 B 级表原文把「监测普通变化」归 B，故②按括号内
   第一义「监测状态转异常」落：`_record_check_locked` 中监测由非
   failed 转入抓取失败的**转换边沿**发一条 A 事件（grade=A、
   alert=down），重复失败不重发、恢复后再失败可再发；建监测时的
   baseline 失败不发。生产当前监测器为 0，此路暂无活样本。
3. **③的源头**：`_patch_goal` 在里程碑「未全勾→全勾」转换时发 A
   事件；保持全勾的后续编辑不重发，取消后重勾可再发。
4. **A 级独立帖机器（kind=`event`）**：同对象（refs 首项；待批用
   合成对象 approval）15 分钟内多事件合并一帖，标题取优先级最高
   （待批>任务>监测>里程碑）、同级取最新一条的事实；正文 ≤3 句
   确定性模板（事实→影响→去哪处理）；why 固定口径「这是你自己的
   事——来自你站内的任务、监测与审批。」；refs 过 `_clean_refs`
   形态审计；30 天过期同 research；**日上限 3 帖**，超限 A 事件
   溢出进 digest 并置于顶部「## 重要事项」段；用户删帖后其簇封存，
   合并窗内不复活；合并刷新只改标题/正文/refs/emoji，createdAt 与
   readAt 永不重写。
5. **digest 降级**：只收 B 级＋溢出；标题「今日动态 · N 件」→
   「今日小结 · N 件」；emoji 脱离写死 📰、按主导 kind 选（同数按
   分组头序）；重建删除 `readAt = None` 一行（已读永不被重建刷回
   未读）；`digestEventKeys` 只跟踪 digest 实际收录集，A 事件进出
   不再触发 digest 重建。research 双线/编辑环/口味账零触碰；事件
   源 `_feed_local_events_locked` 未改（任务事件在 poll 处多带
   `state`/`taskTitle` 原始事实字段，供分级不靠解析文案）。
