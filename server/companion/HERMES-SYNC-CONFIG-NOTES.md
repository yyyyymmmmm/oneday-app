# Hermes 配置侧修复建议（同步制上线配套，2026-11-10）

> 性质：部署窗口执行用的变更建议与验收脚本说明。**本文件只是建议稿，未动任何生产配置**；当前生产 `config.yaml` 的实际取值（尤其 `tools.tool_search`）须在部署窗口先读出来再对照本稿落改，读不到就不许凭本稿猜。
> 依据：规格 `device-sync-design-20261110.md` §5；外部调研 `research_notes/agent-phone-contacts-access-20261110-1348/report.md`（官方文档＋GitHub 实锤）。

## 1. 已知事实（调研实锤，不必再验）

- Hermes 的会话工具集在**会话构造时定格**：中途往配置加的 MCP 服务器，只在执行重载（/reload-mcp）、新开会话或上下文压缩时才进入已有会话。
- 网关/网页会话路径有两类已确认问题：发现流程没启动导致工具集快照为空；发现竞态导致工具被静默丢掉。
- `tools.tool_search` 开启/自动时，MCP 工具被收进工具目录，模型须先搜再用；官方文档自认模型经常不搜、转而宣称「没有这个能力」——2026-11-10 21:47 通讯录答不上就是这个表现。

## 2. 配置变更建议（部署窗口执行，逐项打勾）

1. **device 这台 MCP 服务器保持已注册**（本次工具面从 10 个涨到 21 个，服务器名不变，仍是 `device`，地址与密钥引用沿用现行项，不新增钥匙）。
2. **工具可见性**（规格 §5.2 二选一，部署窗口按当时配置面实测定）：
   - 首选：若 Hermes 支持按服务器豁免工具目录收纳，只给 `device` 豁免，21 个工具直接可见；
   - 备选：若只有全局开关，在工具总数可控的前提下关掉收纳（代价：全部工具常驻、占上下文；落改前先把当前工具总数读出来写进部署记录）。
   - 本地无法预先判定走哪条：取决于生产 Hermes v0.23.0 的配置面与现值，部署窗口第一步就是读 `tools:` 段现值并留痕。
3. **静默过滤三查**（同窗口顺手核查并留痕）：`tools.include/exclude` 没有误筛 device；device 服务器未被禁用；没有按平台的工具集设置把 device 排除。
4. **生效流程定为运维规矩**（规格 §5.1）：`hermes mcp test device` 自检通过 → 重载 MCP 或重启 Hermes（生产动作，单独报批）→ 用**新开的会话**跑三问验收（§3）。旧会话问不到新工具是预期行为，标准答复是「新开一个对话再问」，不许拿旧会话的答复当验收结论。

## 3. 三问验收（脚本）

脚本：`tests/hermes_sync_acceptance.py`（只读验收工具，不改任何配置）。
用法（部署窗口、Hermes 重载完成后执行）：

```
HERMES_BASE=https://<部署域名> HERMES_API_KEY=<登录密钥> \
  python3 tests/hermes_sync_acceptance.py
```

它会新开一个会话，依次问规格 §5.3 的三问，打印模型原答，并按预期口径做关键词核对（点没点出 device 工具、计数答复有没有数字与同步时刻、有没有出现「联系不上」式答复、日历答复有没有覆盖范围）。核对只是启发式，**最终判定以人工读原答为准**；任一问不过，先查 §2 的可见性与生效流程，不许先怀疑手机侧。
