# xcstrings 三方合并自测样本

`merge_xcstrings.py --self-test` 的固定样本。`base/ours/theirs.xcstrings`
是三方输入，`expected-merged.xcstrings` 与 `expected-conflicts.json`
是按规则手定的期望（不经工具生成，防循环验证）。

## 条目来源

真实条目取自 §119/§120 两次合并在 git 历史中的三方版本：

- §119：base `a11c52f` / ours `18c6b39` / theirs `029fa05`（合并 `4d23a29`）
- §120：base `669e5bb` / ours `3885578` / theirs `bfddcbd`（合并 `288dbe4`）

| 键 | 类别 | 来源 |
|---|---|---|
| ` · %lld 个工具` | 三方未动 | §120 实样 |
| `%@ 对话` | 仅一方新增 | §119/§120 实样 |
| `%lld 条已改好，…` | 仅他方新增 | §120 实样 |
| `「%@」正被这些地方用着：%@。…` | 仅他方新增 | §119 实样 |
| `默认服务商（经网关）` | **双方新增冲突**（仅 zh-Hant 异：網關/閘道） | §120 唯一真冲突；历史合并人工裁定取他方，工具口径＝点名＋先取我方待裁 |
| `%lld 未读` | 我方删＋他方未动 → 删 | §120 实样 |
| `主端点（经网关）` | 他方删＋我方未动 → 删 | §120 实样 |
| `构造样本·仅我方改` / `构造样本·双方同改` / `构造样本·双方异改` / `构造样本·删与改相撞` | 改既有键四类 | **构造**——§119/§120 历史里没有「改既有键」与「删改相撞」，按任务口径构造并在此注明 |

## 全量回放验证（2026-11-11，§133 施工时实测）

拿两次历史的完整三方文件跑工具、与真实合并结果逐键比对：

- §119：工具输出与合并结果 `4d23a29` **逐键逐值全等**（2627 键、零冲突）。
- §120：差异恰为预期内三类——①被点名的 1 处冲突（上表，历史取他方、
  工具取我方待裁）；②8 个键工具保留而历史结果没有、1 个键历史结果独有：
  均为那次合并时的人工编辑（旧组合文案一并清理、合并轮新代码顺手补键），
  非并集对账错误。
